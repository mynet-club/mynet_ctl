## 0. 从「架构闭环」到「产品闭环」还差什么

| 维度 | R 段后 | T 段目标 |
|---|---|---|
| 连通 | 单 VM + dry-run 路由 | **多节点 UDP 打洞真通** |

| 交付 | make dist | **CI 出包 → ctl 发布 → 在线升级** |
| 规模 | 1k 会话合成 | **真集群**、多 gateway、可观测 |

## 3. 出口判据

### G3 真隧道（T1）
- 两节点 VPN IP **互 ping**
- `gnb_ctl -s` 显示 PONG；wg `latest handshake` 有效
- 跨驱动：gnb 节点 ping 通 wg 节点网段
- e2e 脚本可重复（`scripts/e2e/g3_tunnel.sh`）

### G4 生产可用（T3）
- 外网 `https://api.mynet.club` 注册登录
- 新节点 10 分钟内走完「注册→密钥→连接→互通」
- `mynet update` 升级不断线

### T5 公测态
- Win/mac 装得上
- 文档可跟做
- 安全复检 0 高危 + 隐私说明

## 5. 排序原则

1. **真通优先于功能堆叠**——T1 不通，T2 全是纸面  
2. **一条可重复 demo > 十个散功能**——T2-7 是产品验收  
3. **密钥与备份与上线同权**——T3-3 不做完不上线  
4. **合成压测不能替代真集群**——T4-6 必须真节点

## 6. 风险

| 风险 | 处置 |
|---|---|
| NAT 打洞失败 | gnb index/proxy 兜底；T1-2 先局域网 |
| 域名/证书未备 | T3-2 可用 nip.io / 自签过渡 |
| 单 VM 不够 | 宿主跑节点 A + VM 跑节点 B（T1-1） |
| back_priv 泄露 | T3-3 备份加密 + 文件权限审计 |
| Quasar 工程量 | T2-6 先四页，不做像素级 |
